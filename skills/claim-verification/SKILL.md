# 结论证据审计

对已有草稿或已完成交付物做第二遍证据审计。除非用户明确要求，不要用本审计替代原任务，也不要把审计自动附加到普通回答中。日常证据意识由全局 `AGENTS.md` 负责，本 Skill 只处理正式的逐条核验。

## 审计流程

1. 只提取会影响决策或完成状态的关键断言：
   - 成功、完整、覆盖、冗余、等价、兼容、安全或当前状态；
   - 数量、版本、时间、性能等可变或可测量结论；
   - 用户特别指定要核查的结论。
2. 为每条断言标注状态：
   - **已验证**：由当前、直接且足够的证据支持；
   - **推断**：证据支持其方向，但没有直接实测；
   - **未知**：证据缺失、过期、不可访问或互相矛盾。
3. 核验证据质量：
   - 检查命令退出码和标准错误，不能把空输出当作成功；
   - 对会改变决策且容易漂移的事实，在成本合理时重新验证；
   - 判断覆盖、冗余、一致或等价时比较实际行为或内容，不能只看名称和描述；
   - 区分已配置、已安装、已启用、已连接与运行可用。
4. 保留不确定性：
   - 不把推断升级成事实；
   - 写明尚未运行或无法运行的检查；
   - 给出能够解决未知项的最小下一步检查。

## 输出格式

先输出紧凑表格：

| 断言 | 状态 | 证据 | 缺口或下一步检查 |
|---|---|---|---|

然后仅在有内容时给出：

- 已确认结论
- 需要修正的结论
- 剩余未知项

## 边界

- 本 Skill 是二次审计流程，不是普通工作的必经步骤。
- 除非用户另外要求修复，否则保持只读。
- 不核查无关紧要的每一句话；聚焦可能误导决策或夸大完成状态的断言。
- 优先使用当前的一手证据和命令结果，不用名称、摘要、记忆或旧结论代替验证。
