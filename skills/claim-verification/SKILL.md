# 断言卫生

四条普适教训：

1. **标注置信度**——报告里每句话只有三种状态：已验证 / 推断 / 猜测。只有实测过的配用肯定语气。"覆盖""冗余""一致"类分析结论默认是推断，除非刚刚 diff/对比过。
2. **零输出 ≠ 成功**——`cmd 2>/dev/null | wc -l` 会把错误吞成 0，0 又被读成"正常"。喂给决策的数字不许吞 stderr；先查存在性（`[ -d ]`）或用退出码，失败要有独立出口。
3. **事实就地验证**——会被下游决策使用的事实，在使用点重新验证一次，不从上游结论继承。一个未验证事实会沿结论链复利放大。
4. **名称相似是弱证据**——判断功能重叠/冗余只看内容比对，不看命名、描述或直觉。
